# AY-LEE BOT — PHASE 1: CORE FOUNDATION

Build Phase 1 of a WhatsApp bot called **AY-LEE BOT**.

IMPORTANT: This is ONLY Phase 1.

Do NOT build the media downloaders, AI, economy, games, antilink, welcome system, sticker commands, or other advanced features yet.

The priority is to create a stable foundation that we can expand later.

---

## 1. TECHNOLOGY

Use:

* Node.js
* TypeScript
* Baileys for WhatsApp Web connectivity
* SQLite for basic persistent data
* dotenv/environment variables
* A modular command architecture

Use current stable versions of dependencies that are compatible with each other.

Before installing packages, check compatibility and avoid deprecated packages where possible.

# 4. WHATSAPP CONNECTION

Create a reliable WhatsApp connection using Baileys.

The bot must:

* initialize the WhatsApp connection
* display authentication/pairing information in the console as supported by the selected Baileys version
* persist authentication credentials
* reconnect after temporary connection failures
* handle logged-out sessions correctly
* handle connection errors
* avoid infinite reconnect loops
* prevent the bot from processing its own messages
* gracefully shut down when the Replit process stops

Do not print private authentication credentials into logs.

---

# 5. AUTHENTICATION

Make authentication suitable for Replit.

If QR authentication is the simplest reliable approach with the selected Baileys version, implement QR authentication.

If pairing-code authentication is supported reliably by the selected version, make it optional.

The console should clearly tell the owner what to do.

Example:

==============================
AY-LEE BOT
==========

Waiting for WhatsApp authentication...

[authentication instructions]

Do not pretend authentication succeeded if it did not.

Example configuration:

Read values from environment variables.

Provide sensible defaults for non-sensitive settings.

Normalize phone numbers before comparing them.

# 7. COMMAND SYSTEM

Create a reusable command interface.

Each command should contain:

* name
* aliases
* category
* description
* usage
* permissions
* execute function

Example concept:

command.name = "ping"
command.aliases = ["p"]
command.category = "general"
command.description = "Check bot response"
command.usage = ".ping"

Create an automatic command loader.

The system should scan the commands directory and register commands automatically.

Adding a new command later should NOT require rewriting the command handler.

---

# 8. COMMAND PARSER

The bot uses:

.

as the default prefix.

Example:

.ping

The parser should:

1. Check whether the message begins with the configured prefix.
2. Extract the command.
3. Extract arguments.
4. Convert the command name to lowercase.
5. Find the registered command.
6. Check permissions.
7. Execute it.

If the message is not a command, ignore it for now.

Do not send "unknown command" responses for every ordinary message.

# 16. DATABASE

Create a basic SQLite database.

Tables should include at least:

users
groups
bot_settings

For users store only basic information needed by the bot.

For groups store:

* group JID
* group name if available
* created/updated timestamps

For bot settings store:

* setting name
* setting value

Create clean helper functions so Phase 2 can add:

* antilink settings
* welcome settings
* warnings
* group preferences

without redesigning the database.

---

# 17. PERMISSION FRAMEWORK

Create reusable permission functions:

isOwner()
isGroup()
isGroupAdmin()
isBotAdmin()

For Phase 1, only the owner check needs to be actively used.

The other functions can be prepared for Phase 2.

Do NOT implement fake permission checks.

---

# 18. MESSAGE HANDLER

Create a central message handler.

For every supported incoming message:

* identify chat JID
* identify sender JID
* determine private/group
* extract message text
* determine command
* execute command
* catch errors

Ignore unsupported message formats safely.

Do not crash when:

* a message is deleted
* a message has no text
* sender information is unavailable
* a group metadata request fails

---

# 19. LOGGING

Create a simple logger.

Examples:

[INFO] Starting AY-LEE BOT
[INFO] Loading commands...
[INFO] Loaded 6 commands
[INFO] Connecting to WhatsApp...
[INFO] WhatsApp connected
[COMMAND] .ping | user | chat

Do not log authentication secrets.

Do not unnecessarily log private message contents.

---

# 20. ERROR HANDLING

The bot must not crash because a command fails.

Wrap command execution in proper error handling.

If a command throws an error:

* log the technical error
* send a simple user-friendly error message
* continue running the bot

Do not expose stack traces to WhatsApp users.

* hard-code passwords
* commit authentication credentials
* execute arbitrary shell commands from WhatsApp messages
* execute arbitrary JavaScript from user messages

Use Replit Secrets/environment variables for sensitive configuration.
